HFT Orderbook Flow & Metrics Engine

Высокопроизводительный асинхронный движок на **Rust** для перехвата тиковых данных и расчета метрик рыночной микроструктуры в реальном времени.

Архитектурные фичи (Low-Latency гайд):

*   **Zero-Copy Ingestion:** Никакого тяжелого парсинга JSON через стандартные структуры. Модуль сети сканирует сырые байты (`&[u8]`) по сигнатурам. Процессор не тратит время на выделение памяти (динамические строки) под каждый входящий тик.
*   **Lock-Free Pipeline:** Сетевой поток (Async Runtime) и математический движок (Sync Engine) полностью изолированы друг от друга и крутятся на разных физических ядрах процессора. Данные передаются через сверхбыстрый канал `crossbeam_channel::bounded`. Сетевой джиттер никогда не затормозит расчет метрик.
*   **Static RingBuffer:** Никаких векторов (`Vec`) с динамическим расширением памяти. Для скользящих окон (CVD) написан кастомный кольцевой буфер фиксированного размера. Вся математика крутится в L1/L2 кэше процессора.
*   **Пакетный ввод-вывод (I/O):** Сигналы и метрики упаковываются в компактный бинарный формат через `bincode` и сбрасываются на SSD пакетами по 100 штук, минимизируя задержки системных вызовов ядра ОС.

Структура проекта

Система построена по принципу модульного конвейера (Separation of Concerns):

Используйте код с осторожностью.
crate bot
├── mod common       <- Общие контракты данных (Tick, Signal, Side), PartialEq + Copy
├── mod ingestion    <- Асинхронный захватчик WebSockets (Binance Futures), Zero-Copy парсер
├── mod engine       <- OS-поток математики, RingBuffer, расчет CVD и скорости тиков
└── mod execution    <- Эмулятор исполнения ордеров с симуляцией Slippage и задержки сети

Как запустить в продакшене

1. Требования к железу
*   ОС: Linux (Ubuntu 22.04 LTS / 24.04 LTS рекомендуется).
*   Локация: Для минимизации лагов до 1-2 мс рекомендуется VDS в Франкфурте (AWS eu-central-1) или Токио (AWS ap-northeast-1).
*   Сеть: Гигабитный порт (`1 Gbps`).

2. Сборка в максимальный Production-режим
Чтобы компилятор `rustc` выжал из кода все соки, отключил дебаг-логи и оптимизировал перестановку инструкций под процессор, собирай строго с флагом `--release`:

```bash
cargo build --release
cargo run --release
```

Движок создаст файл `market_data.bin` в корневой папке и начнет стримить туда упакованные HFT-метрики в реальном времени.

---

Квантовый контур (Связь с Python)

Бинарный файл `market_data.bin` — это готовое топливо для твоего `Research` контура. Из-за сериализации через `bincode` он весит копейки. 

Достаточно забрать его по SFTP на домашнюю машину, прочитать одной строчкой в Python, и ты получаешь идеальный датасет для проверки скальпинговых гипотез в `Pandas / Numpy` без пропусков данных и `look-ahead bias` (эффекта заглядывания в будущее).
